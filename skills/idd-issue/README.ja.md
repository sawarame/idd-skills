# idd-issue

[English](./README.md) | [日本語](./README.ja.md)

アイデアや課題のメモを起点に、リポジトリのコードや規約を読み取り専用で調査しながら AI と対話的に要件を整理し、後続の `/idd-implement` ですぐに実装できる粒度の GitHub Issue を **ローカルでログイン中の `gh` ユーザーとして** 作成するスキル（[`SKILL.md`](./SKILL.md)）です。

---

## 使い方・プロンプト例

AI コーディングエージェント上で `/idd-issue` と入力するか、自然文で `idd-issue` の利用を指示してください。

### 1. ざっくりしたアイデアから壁打ちして Issue を作る

```text
/idd-issue 設定画面にダークモードの切り替え機能を追加したい
```

```text
idd-issue を使って、CSV エクスポート機能の要件を整理して GitHub Issue を作成してください
```

### 2. 不具合・バグのメモから原因調査を踏まえて Issue 化する

```text
/idd-issue ダッシュボード画面をリロードするとログアウトされる不具合を調査して、修正用の Issue にまとめたい
```

### 3. まだ内容が固まっていない状態から対話を始める

```text
/idd-issue
```

*（何を作りたいか・直したいかを AI からヒアリングし、リポジトリの状況を踏まえて質問しながら要件を具体化します。）*

### 4. 対象外（Out of Scope）やラベル提案の希望を添えて依頼する

```text
/idd-issue エクスポート処理をストリーミング対応にリファクタリングしたい。UI の変更は対象外にして、既存の適切なラベルも提案してください
```

### 5. 起票した Issue を `idd-implement` に引き継ぐ

Issue（例: `#123`）が作成されたら、そのまま自律実装へ進めます：

```text
/idd-implement #123
```

---

## 実行フローの概要

1. **読み取り専用でのリポジトリ調査**: `gh auth status` やプロジェクト規約（`CONTRIBUTING.md` / `AGENTS.md` / `README*`）、`.github/ISSUE_TEMPLATE/`、関連ソースコード、オープン中の既存 Issue（重複防止）、利用可能なラベルを確認します（ファイル編集やブランチ操作は行いません）。
2. **対話型ブレスト・要件整理**: 背景・目的、具体的な要件・仕様、対象外（Out of Scope）、技術的考慮事項、受け入れ条件をやり取りしながら明確にします。
3. **投稿前の完全プレビューと承認待ち**: 対象リポジトリ、投稿アカウント、タイトル、ラベル／Assignee（任意）、本文の全文プレビューを表示し、ユーザーの明示的な許可を得てから進みます。
4. **ローカルの `gh` ユーザーで起票**: `gh issue create` を直接実行し、ご自身の GitHub アカウントで Issue を作成します。
5. **結果報告と次のステップ案内**: 作成した Issue 番号・URL を報告し、`/idd-implement <番号>` を案内します。

---

## 前提条件とポイント

- **前提条件**:
  - **GitHub CLI (`gh`)** が `gh auth login` で認証済みであること
  - 対象の GitHub リポジトリに紐づくローカルリポジトリ内で実行すること
- **常にローカルの `gh` ユーザーで投稿**: `gh-as-bot.mjs` や GitHub App Bot は使わず、`（🤖AIによる投稿）` などの AI 投稿マーカーも付与しません。
- **読み取り専用で安全**: ブレスト・ドラフト作成中にファイル編集、ブランチ切り替え、コミットは一切行いません。
- **会話言語に合わせた作成**: リポジトリ規約で固定言語が指定されていない限り、ユーザーとの会話と同じ言語で Issue のタイトル・本文を作成します。
- **Projects v2 は対象外**: 標準の `gh issue create` の範囲（タイトル・本文・任意のラベル／Assignee）のみを扱います。
