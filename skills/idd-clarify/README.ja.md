# idd-clarify

[English](./README.md) | [日本語](./README.ja.md)

既存の GitHub Issue 番号を指定して、Issue 本文・既存コメントおよびリポジトリのコードを読み取り専用で調査し、仕様として不足・曖昧な点を洗い出した上で、ユーザーと対話形式で仕様を固め、**ローカルでログイン中の `gh` ユーザーとして** 固まった仕様を Issue コメントに追記するスキル（[`SKILL.md`](./SKILL.md)）です。

---

## 使い方・プロンプト例

AI コーディングエージェント上で `/idd-clarify` と入力するか、自然文で `idd-clarify` の利用を指示してください。

### 1. 既存 Issue の不足している仕様を洗い出して固める

```text
/idd-clarify #123
```

```text
idd-clarify を使って GitHub Issue #123 を読み込み、仕様として不足している箇所を確認しながら固めてください
```

### 2. GitHub の Issue URL をそのまま渡して実行する

```text
/idd-clarify https://github.com/owner/repo/issues/123
```

### 3. `idd-implement`（Goal A / `question` ラベル）の確認事項を対話で解消する

`/idd-implement #123` が不明点ありで確認コメントを投稿し `question` ラベルを付けて終了した場合に、その質問内容も含めて対話で仕様を確定できます：

```text
/idd-clarify #123
```

*（Issue 本文と既存コメントの質問事項を読み込み、対話で仕様を確定した上で、承認後に確定仕様コメントを投稿し、希望に応じて `question` ラベルも外します。）*

### 4. 仕様を固めた Issue を `idd-implement` に引き継ぐ

`#123` に確定仕様コメントを投稿できたら、そのまま自律実装へ進めます：

```text
/idd-implement #123
```

## 実行フローの概要

1. **読み取り専用での Issue・リポジトリ調査**: `gh auth status` の確認後、`gh issue view <番号> --comments` で対象 Issue 本文・既存コメントを取得し、プロジェクト規約や関連ソースコードを読み取り専用で調査します（ファイル編集やブランチ操作は行いません）。
2. **仕様の不足・曖昧点の洗い出し**: 対象範囲（Out of Scope）、機能仕様・入出力、エッジケース・エラーハンドリング、技術的な設計判断、受け入れ条件、および既存コメント内の未回答の質問について不足点を整理します。
3. **対話形式での仕様確認**: すでに明確な内容を共有した上で、影響の大きい不明点から順に、コードベースを踏まえた選択肢と推奨案を提示しながらユーザーと仕様を確定します。
4. **投稿前の完全プレビューと承認待ち**: 対象リポジトリ、対象 Issue、投稿アカウント、`question` ラベル解除の有無（付与時）、およびコメント本文の全文プレビューを表示し、ユーザーの明示的な許可を得てから進みます。
5. **ローカルの `gh` ユーザーでコメント投稿**: `gh issue comment` を直接実行し、ご自身の GitHub アカウントで確定仕様をコメント追記します（承認時は `question` ラベルも解除します）。
6. **結果報告と次のステップ案内**: 投稿したコメント／Issue の URL を報告し、`/idd-implement <番号>` を案内します。

---

## 前提条件とポイント

- **前提条件**:
  - **GitHub CLI (`gh`)** が `gh auth login` で認証済みであること
  - 対象の GitHub リポジトリに紐づくローカルリポジトリ内で実行すること
- **常にローカルの `gh` ユーザーで投稿**: `gh-as-bot.mjs` や GitHub App Bot は使わず、`（🤖AIによる投稿）` などの AI 投稿マーカーも付与しません。
- **元の Issue 本文を保持**: 元の説明文を上書きせず、`gh issue comment` による新規コメントとして確定仕様を記録します。
- **読み取り専用で安全**: 仕様確認・ドラフト作成中にファイル編集、ブランチ切り替え、コミットは一切行いません。
- **Issue スレッドの言語に合わせた作成**: リポジトリ規約で固定言語が指定されていない限り、既存の Issue スレッドと同じ言語（または会話言語）でコメントを作成します。
- **Projects v2 は対象外**: GitHub Projects v2 への登録やステータス変更は行いません。
